# 🖼️ Profile Image API

> **Base path:** `/api/v1/profile/image`  
> **Auth:** Session JWT via `session-token` header — NOT an OAuth2 Bearer token

| Auth type | Header | Source |
|-----------|--------|--------|
| Session JWT | `session-token: <session-jwt>` | `POST /api/v1/session` or `POST /api/v1/session/token` |

> [!NOTE]
> This domain uses the **session token** (short-lived JWT issued by the session endpoint), not the OAuth2 Bearer JWT used by other domains. The user identity (userId + applicationId) is extracted from the session token claims server-side — you do not pass them as separate parameters on every request.

> [!NOTE]
> Profile images are stored in **Supabase Storage**. Uploads go directly to the configured Supabase bucket; retrieval returns either raw bytes or a time-limited signed URL from Supabase.

## 🔵 POST /api/v1/profile/image/application/{applicationId}

> Upload a profile image for the authenticated user within an application context.

> [!TIP]
> PNG and JPEG are the recommended formats. Keep images under 5 MB for best performance.

### 📋 Request Headers

| Header | Required | Description |
|--------|----------|-------------|
| `session-token` | ✅ | Active session JWT |
| `Content-Type` | ✅ | `multipart/form-data` |

### 🛤️ Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `applicationId` | `UUID` | ✅ | Application context for the image |

### Request Body (multipart/form-data)

| Part | Type | Required | Constraints | Description |
|------|------|----------|-------------|-------------|
| `image` | `file` | ✅ | PNG or JPEG recommended, max ~5 MB | Raw image bytes |

### 📡 Responses

| Status | Meaning | When |
|--------|---------|------|
| `201 Created` | Image uploaded | Stored successfully in Supabase Storage |
| `400 Bad Request` | Invalid input | Null applicationId or missing `image` part |
| `401 Unauthorized` | Bad session | Session token missing, expired, or invalid |
| `500 Internal Server Error` | Storage error | Supabase Storage unreachable or write failure |

**Response `201 Created`:**

```json
{
  "storageKey": "profile-images/a1b2c3d4-e5f6-7890-abcd-ef1234567890/avatar.png",
  "uploadedAt": "2026-07-12T14:30:00Z"
}
```

### 💡 Example

```bash
curl -k -s -X POST \
  "https://<host>:8084/api/v1/profile/image/application/a1b2c3d4-e5f6-7890-abcd-ef1234567890" \
  -H "session-token: <session-jwt>" \
  -F "image=@/path/to/avatar.png;type=image/png"
```

## 🟢 GET /api/v1/profile/image/

> Download the profile image bytes for the authenticated user.

> [!NOTE]
> No path parameters are needed. The user's identity is resolved from the `session-token` claims. The response body is the raw binary image — save it directly to a file or pipe it to a viewer.

### 📋 Request Headers

| Header | Required | Description |
|--------|----------|-------------|
| `session-token` | ✅ | Active session JWT |

### 📡 Responses

| Status | Meaning | When |
|--------|---------|------|
| `200 OK` | Image bytes | Image found — body is raw binary |
| `401 Unauthorized` | Bad session | Token missing, expired, or invalid |
| `404 Not Found` | No image | No image uploaded for this user |
| `500 Internal Server Error` | Storage error | Supabase Storage retrieval failure |

**Response `200 OK`:**

```
Content-Type: image/png
Body: <binary image bytes>
```

### 💡 Example

```bash
# Download to file
curl -k -s -X GET "https://<host>:8084/api/v1/profile/image/" \
  -H "session-token: <session-jwt>" \
  --output avatar.png

# Display file size
curl -k -s -X GET "https://<host>:8084/api/v1/profile/image/" \
  -H "session-token: <session-jwt>" \
  -o /dev/null -w "Size: %{size_download} bytes\n"
```

## 🟢 GET /api/v1/profile/image/application/{applicationId}/reference

> Obtain a time-limited signed URL for the authenticated user's profile image in the given application context.

> [!TIP]
> Use this endpoint when you need to embed the image in a browser, share it with a frontend client, or pass it to a third-party service. The signed URL is generated by Supabase Storage and expires — do not cache it indefinitely.

> [!CAUTION]
> Do not store the signed URL in a database or long-lived cache. Fetch a fresh reference close to the time you need it.

### 📋 Request Headers

| Header | Required | Description |
|--------|----------|-------------|
| `session-token` | ✅ | Active session JWT |

### 🛤️ Path Parameters

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `applicationId` | `UUID` | ✅ | Application context |

### 📡 Responses

| Status | Meaning | When |
|--------|---------|------|
| `200 OK` | Reference returned | Signed URL generated |
| `401 Unauthorized` | Bad session | Token missing, expired, or invalid |
| `404 Not Found` | No image | No image uploaded for this user in this application |
| `500 Internal Server Error` | Storage error | Supabase signed URL generation failed |

**Response `200 OK`:**

```json
{
  "reference": "https://jygwixrpoxcrltmeshyl.supabase.co/storage/v1/object/sign/profile-images/a1b2c3d4-e5f6-7890-abcd-ef1234567890/avatar.png?token=eyJ...",
  "expiresAt": "2026-07-12T15:30:00Z"
}
```

### 💡 Example

```bash
curl -k -s -X GET \
  "https://<host>:8084/api/v1/profile/image/application/a1b2c3d4-e5f6-7890-abcd-ef1234567890/reference" \
  -H "session-token: <session-jwt>"
```

**Render the image in HTML using the reference:**

```html
<img src="{{ reference }}" alt="Profile image" />
```

## 🚨 Error Reference

| Status | Code | Description |
|--------|------|-------------|
| `400` | Bad Request | Null applicationId or missing `image` multipart part |
| `401` | Unauthorized | Session token missing, expired, or signature invalid |
| `404` | Not Found | No profile image stored for this user / application |
| `500` | Internal Server Error | Supabase Storage write or read failure |
